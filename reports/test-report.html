Testing Approach

  • Playwright is used for web UI automation.
  • pytest is used for test execution and fixtures.
  • Requests is used for API testing.
  • API-created data is used for efficient integration testing.
  • Unique test data helps prevent parallel execution conflicts.
  • Tenant isolation is validated at both UI and API levels.
  • Playwright's automatic waiting is preferred over fixed sleeps.
  • BrowserStack is proposed for real mobile/browser coverage.
  • CI/CD can execute smoke tests on pull requests and regression tests on scheduled builds.

Flaky Test Prevention

  • Use Playwright auto-waiting and retrying assertions.
  • Avoid unnecessary time.sleep().
  • Use stable locators.
  • Wait for meaningful application states.
  • Use isolated browser contexts.
  • Generate unique test data.
  • Keep tests independent.
  • Collect screenshots/traces when failures occur.
  • Investigate the root cause rather than relying only on retries.

Test Data

Test data should be isolated between test executions. Project names can include a unique identifier to prevent collisions during parallel execution. 

Automation Project <unique-id>

Credentials and API tokens should be supplied through environment variables or CI/CD secret storage rather than being committed to source control.
